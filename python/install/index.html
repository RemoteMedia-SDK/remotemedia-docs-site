    Install the Python APIs¶

    Choose local execution when Python should own a native runtime, or remote control when the runtime already runs on Scaling. Use separate environments: the published client and current checkout have different APIs despite both reporting version 0.2.0.

    Tested environments¶

    These checks ran on Windows 11 x64 with CPython 3.12.3, in fresh virtual environments without system packages, on November 15, 2026. CPU text examples require no model download or GPU.

    Profile Client Native component Verified
    Local FFI PyPI remotemedia-client==0.2.0; iceoryx2==0.9.0 Supplied remotemedia_ffi-0.4.4-cp310-abi3-win_amd64.whl Unary echo, streaming, in-process control, direct node contract, timeout/close
    Scaling control Sibling SDK checkout; iceoryx2==0.10.0 No FFI in the client environment; separate Entry + runner binaries Authenticated deploy, join admission, publish/subscribe, teardown
    Python worker SDK checkout including the RPC channel-header fix; iceoryx2==0.10.0 Locally built remotemedia_ffi-0.4.4-cp311-abi3-win_amd64.whl FFI, streaming, local control, real worker configuration, RPC, normal process exit

    Other operating systems, Python versions, CUDA nodes, and native feature combinations have not been validated by these guides. The worker wheel is a development build for these CPU text checks. Package metadata alone does not establish support.

    A supplied Windows wheel is required

    A binary-only PyPI resolution for FFI 0.4.4 found no usable wheel for this environment. Obtain the matching native artifact from your runtime build/release workflow. A plain install may attempt a source build. The artifact used here is identified below; this repository does not redistribute it.

    Local execution¶

    Run these PowerShell commands from the documentation repository. They assume uv and CPython 3.12.3 are installed. Replace the wheel path with your supplied artifact.

    uv venv --python 3.12.3 .venv-runtime
$wheel = "C:\path\to\remotemedia_ffi-0.4.4-cp310-abi3-win_amd64.whl"
Get-FileHash -Algorithm SHA256 -LiteralPath $wheel
uv pip install --python .venv-runtime/Scripts/python.exe -r examples/python/requirements-local.txt $wheel
.venv-runtime/Scripts/python.exe examples/python/doctor.py --require-ffi
.venv-runtime/Scripts/python.exe examples/python/ffi_echo.py

    Expected final output: hello. The diagnostic prints the imported client path, native path, and versions. Optional model-import warnings can appear; these text examples do not require those models.

    The tested wheel SHA-256 is:

    28c33e00174973c3a3421426207066ab0487d364f51ba61d0f502d456f771426

    Its distribution version is 0.4.4; get_runtime_version() reports native runtime 0.4.1. Its build commit is unverified. The artifact filename's ABI tag and the current checkout's Python minimum are different metadata; neither expands the tested matrix above.

    The local requirements pin the client and its resolved dependencies. psutil is included only for the process-cleanup checks.

    Authenticated Scaling control¶

    Place this repository beside remotemedia-sdk. Install the checkout client, which supplies the token= parameter missing from the published client:

    uv venv --python 3.12.3 .venv-control
uv pip install --python .venv-control/Scripts/python.exe -r examples/scaling/requirements.txt -e ../remotemedia-sdk/clients/python
.venv-control/Scripts/python.exe examples/python/doctor.py

    The Scaling requirements pin dependencies used for this run, including the authentication harness. No native FFI package is needed in this environment. Proceed to Connect to Scaling for the Entry/runner example.

    A version string alone cannot distinguish these clients. The reviewed checkout's attach() includes token and participant; see API reference. Do not overlay that checkout onto the local wheel environment without validating native/worker compatibility.

    Verify your environment¶

    .venv-runtime/Scripts/python.exe scripts/verify_examples.py

    The verifier runs examples in fresh processes, bounds each run, and writes .run/runtime/results.json plus logs. Forced process cleanup is a failure, even when output was correct.

    Python worker environment¶

    Use the checkout client and its matching native build for the worker walkthrough. The published client cannot discover this example's dotted class path. The checkout must also include the RPC reply-reader fix that removes the worker's rpc text-channel header before parsing JSON; the reviewed file hash is recorded in sources.json.

    uv venv --python 3.12.3 .venv-worker
$workerWheel = "C:\path\to\remotemedia_ffi-0.4.4-cp311-abi3-win_amd64.whl"
uv pip install --python .venv-worker/Scripts/python.exe -r examples/python/requirements-worker.txt ../remotemedia-sdk/clients/python $workerWheel
.venv-worker/Scripts/python.exe examples/python/doctor.py --require-ffi
.venv-worker/Scripts/python.exe scripts/verify_examples.py --worker

    Install the client normally, as shown, so it and the native extension share the same package directory. The worker requirements pin the tested dependencies. On Windows, the host and worker also need write access to the iceoryx2 paths under C:\Temp; see IPC troubleshooting.

    The tested worker wheel SHA-256 is 735300c727f2c72d3c26b4ff022e36ad6fa0dcaf8e4e6de6776c54dca5cccb55. It was built with Maturin 1.16.0, the dev profile, default FFI features disabled, and extension-module enabled (which also enables python). The native module reports 0.4.1. This repository retains the source/build fingerprints in its planning evidence; the wheel itself is a local artifact, not a published download.

    Continue with local FFI, Scaling control, or node authoring.

    Advanced Python (MS2) profile¶

    The advanced guides use a separate Windows x64 / CPython 3.12.3 environment and the captured checkout client with the RPC reply-header fix. Use the worker dependency pins and an MS2 native wheel built with extension-module,grpc,remotemedia-core/python-source-plugin. The earlier MS1 wheel has neither gRPC serving nor source-plugin loading enabled.

    uv venv --python 3.12.3 .venv-ms2
$ms2Wheel = "C:/path/to/ms2/remotemedia_ffi-0.4.4-cp311-abi3-win_amd64.whl"
uv pip install --python .venv-ms2/Scripts/python.exe -r examples/python/requirements-worker.txt ../remotemedia-sdk/clients/python $ms2Wheel
$env:REMOTEMEDIA_PYTHON_SRC = (Resolve-Path ../remotemedia-sdk/clients/python).Path
.venv-ms2/Scripts/python.exe scripts/verify_examples.py --milestone2

    Build the wheel with Maturin 1.16.0 from a compatible SDK/base/plugin-SDK workspace. The validation build used --profile dev --no-default-features --features extension-module,grpc,remotemedia-core/python-source-plugin. Its artifact hashes and captured source identity are retained in the repository's MS2 validation record. The distribution is still 0.4.4 and the native runtime reports 0.4.1; distinguish builds by features and hashes, not those version strings alone. This repository does not distribute the wheel.

    The source-plugin gate uses uv on PATH to provision its environment and install packaging==25.0. It has a 150-second outer deadline. Other examples have a 65-second process deadline. The verifier records functional results, descendant cleanup, and copy-accounting shutdown errors separately.

    Python WebRTC profile¶

    Use a separate environment: aiortc 1.14.0 uses the tested PyAV 16.1.0, while the native worker profile pins PyAV 19.0.2.

    uv venv --python 3.12.3 .venv-media
uv pip install --python .venv-media/Scripts/python.exe -r examples/scaling/requirements-media.txt ../remotemedia-sdk/clients/python
.venv-media/Scripts/python.exe examples/scaling/run.py --media --bin-dir C:/path/to/scaling/debug

    No FFI extension is needed in this media client environment. Entry and runner are separate native processes. For the --tools example, build the runner with --features loadable,python-source-plugin, supply the source plugin on the runner's filesystem, and select its matching Python client with REMOTEMEDIA_PYTHON_SRC. See Python WebRTC for the complete media flow.
